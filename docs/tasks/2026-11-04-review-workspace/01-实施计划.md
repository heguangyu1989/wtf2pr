# 代码审查工作区重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The main agent implements; independent fresh-eyes agents perform the review cycles required by iterative-feature-delivery.

**Goal:** 交付统一、可高效浏览文件的代码审查工作区，支持三种 diff 来源和完整文件新旧版本查看。

**Architecture:** 保留 Vue 3 + Tailwind 与 Go/Gin 分层。后端在现有 Git 模块上扩展严格类型的分支 diff 和文件内容读取；前端以来源选择、文件树、diff 和完整文件弹窗组成工作区，App 继续负责 Review/导出等全局状态。

**Tech Stack:** Go 1.25.4、Gin、Vue 3.5、Vite 8、Tailwind CSS 4、Node `node:test`、浏览器 E2E。

**Spec:** `docs/tasks/2026-11-04-review-workspace/00-feature目标.md`

## Global Constraints

- 分支固定为 `feat/review-workspace-redesign`，不为子任务另开分支。
- 不引入 UI、图标、语法高亮或前端测试框架依赖。
- 分支对比只支持本地分支，语义固定为 `git diff <target>...HEAD`。
- 保留历史 Review JSON、working/commit API 与 Commit 评论行为。
- 文件列表取消分页，不引入虚拟滚动；Commit 下拉列表分页保留。
- 前后端通信使用明确结构体，不使用临时请求/响应 map。
- 未经人类另行明确指示，不执行 commit、push、MR；每个任务的“检查点”仅更新看板并检查 diff。
- 文档只写实跑结果，环境缺失标 SKIP，不把 SKIP 写成 PASS。

## Review Focus

- 恶意或异常路径（绝对路径、`..`、符号链接、非 diff 文件）：必须拒绝且不能读取仓库外内容；Task 2 的 Go 测试固定该行为。
- 重命名、新增、删除、空文件和二进制的新旧侧：必须返回对应版本或明确空/二进制状态；Task 2 与 Task 6 分别覆盖 API 和界面。
- 快速切换来源、Commit、分支和弹窗新旧侧：慢响应不得覆盖新选择；Task 5 与 Task 8 分别检查请求取消和真实浏览器竞态。
- 深层目录、数字文件名、同分类文件和反向排序：顺序必须确定且目录结构不丢失；Task 3 的纯函数测试覆盖。
- localStorage/Clipboard 不可用、弹窗键盘关闭和焦点恢复：功能不得崩溃，焦点必须可控；Task 6 与 Task 8 检查降级及真实交互。

- [ ] **Step 3: 实现纯函数**

```js
export function getFilePath(file) {
  return file?.newFile || file?.oldFile || ''
}

export function getFileCategory(filePath) {
  const p = filePath.toLowerCase()
  const name = p.split('/').at(-1)
  if (/(^|\/)(__tests__|tests?)(\/|$)/.test(p) || /\.(test|spec)\.[^.]+$/.test(name) || /_test\.go$/.test(name)) return 'test'
  if (/(^|\/)docs\//.test(p) || /\.(md|mdx|rst|adoc|asciidoc)$/.test(name)) return 'document'
  return 'other'
}
```

比较器使用 `Intl.Collator(undefined, { numeric: true, sensitivity: 'base' })`，冲突时用原始路径作稳定次级比较。`sortFiles` 返回新数组；`buildFileTree` 返回 `{ name, path, type, file?, children }`，目录始终在文件前，方向只反转同类型节点排序。“测试优先”仅将 test 类排到其他类之前，“文档优先”仅将 document 类排到其他类之前；同组继续按路径排序，反向时组顺序和组内路径一起反转。

async function loadDiff() {
  controller?.abort()
  const serial = ++requestSerial
  controller = new AbortController()
  loading.value = true
  error.value = ''
  try {
    const target = { ...props.target }
    const data = await getDiff(target.type, target.commit, target.base, { signal: controller.signal })
    if (serial !== requestSerial) return
    diffData.value = data
    preserveOrSelectFirstFile(data.files)
  } catch (e) {
    if (serial === requestSerial && e.name !== 'AbortError') {
      diffData.value = null
      error.value = e.message
    }
  } finally {
    if (serial === requestSerial) loading.value = false
  }
}

## 最终实现补充

以下为三轮评审后的实际收口，替代早期计划中的对应实现细节：

- 文件授权不再依赖展示 patch 的路径文本，working/commit/branch 统一使用 `git diff/diff-tree --raw -z -r -M` 的 NUL 元数据；diff-tree 递归和 rename 检测与 patch 命令一致，merge commit 保留原生合并语义。
- 完整文件响应仅保留 `content/exists/isBinary`。按请求侧精确匹配真实路径，支持重命名环、同路径删除+未跟踪新增及文本/二进制互转。
- Review ID 使用安全字符白名单并兼容 `feature_x` 等旧自定义 ID；不再限定 UUID。
- Commit 评论采用水合状态，完成前禁止编辑、保存和导出。初始化、保存、导出、历史详情和模板均使用 serial/revision，模板另以 pending 计数清除 loading。
- Review 写操作使用前端 mutation 锁和服务端 RWMutex，避免保存期间切换文件以及 active Review 路径与 Store 快照竞争。
- 最终实测为 91 个顶层 Go 测试函数和 33 个 Node 测试；真实浏览器关键路径通过，三轮 JSON/HTML 评审报告及目录、工作目录专项报告均已保留。目录名可选中筛选，箭头独立折叠，平铺与右侧 diff 使用同一目录结果。
- 工作目录切换使用 `POST /api/config/workdir`，校验直连 loopback、可信本机 Origin/Host、绝对目录与 Git 仓库根目录；切换与 Review 复合操作共用互斥。前端成功后回到 working 并保留 Review 文件，初始化慢响应、旧分支、旧导出与 Commit 缓存均不得跨仓库覆盖。A/B 真实仓库完成三种 diff、目录筛选、行级评论、非法路径与受控慢配置竞态验证。
