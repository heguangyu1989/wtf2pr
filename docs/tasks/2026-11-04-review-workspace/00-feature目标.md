# 代码审查工作区重构设计

## 核心目标

重构 WTF2PR 代码审查工作区，使本地开发者能够高效切换 diff 来源、浏览和排序变更文件，并在不丢失审查上下文的情况下查看完整文件。

本设计已经过对话确认；实施以本文档为验收基准。

## 范围与非目标

### 范围内

- 重新设计代码审查页面及共用导航的视觉与布局。
- 文件列表支持树形、平铺、连续滚动、内置规则排序和本地偏好保存。
- diff 来源支持当前未提交、指定 Commit、当前分支与目标本地分支的三点对比。
- 通过弹窗查看变更前或变更后的完整文件。
- 保持历史 Review、导出、模板和现有 Commit 评论能力。
- 增加后端集成测试、前端纯函数测试、真实 API 冒烟和浏览器端到端验证。

### 非目标

- 不提供任意 glob 排序规则编辑器。
- 不支持远程分支、自定义两个 Commit 对比或合并 Commit 展示语义调整。
- 不引入 UI、图标、语法高亮或前端测试框架依赖。
- 不重构 Review 存储格式，不改变现有 working/commit 评论权限与历史数据兼容性。
- 不处理与本次工作区重构无关的缺陷。

## 验收标准

1. 三种 diff 来源可切换，加载、空数据、错误和快速连续切换均表现正确。
2. 分支对比使用 `git diff <target>...HEAD`，不包含未提交修改；目标分支默认优先 `main`、其次 `master`。
3. 文件列表无分页，树形和平铺均可连续滚动；测试、文档、类型和路径排序确定且可反向。
4. 文件选中态、评论数、增删状态和视图偏好在对应交互后正确更新。
5. 完整文件弹窗可查看新旧版本，支持行号、复制、Esc 关闭及新增、删除、二进制、空文件和错误状态。
6. 文件内容 API 仅可读取请求对应的仓库内文件，拒绝路径穿越和仓库外路径。
7. 现有历史 Review、导出、模板和 Commit 评论链路无回归。
8. lint、前端测试与构建、Go 全量测试与构建通过；真实浏览器完成多轮点击端到端验证。
9. 至少三轮评审循环无未解决的 Critical/Important，报告和任务看板记录真实结果。

## 已选方案

在现有 Vue 3、Tailwind CSS、Go/Gin 架构上重构，不引入组件库。将 Working tree 和 Commit Tab 合并为统一「代码审查」工作区，历史 Review 和导出模板继续作为独立导航。新增职责单一的来源选择、文件浏览和完整文件弹窗组件，并向后兼容地扩展现有 API。

## 页面与视觉设计

- 使用全宽、紧凑的专业开发工具布局，移除工作区 `max-w-7xl` 限制。
- 顶栏保留 Review 标识、保存状态、新建、导出、保存和帮助，区分主次操作。
- 代码审查页顶部使用分段控件切换来源；来源相关参数与 diff 摘要位于同一上下文区域。
- 左侧文件栏桌面端约 280px，右侧 diff 独立滚动；窄屏改为上下布局。
- 使用中性色、精细边框、单一强调色和等宽代码字体；增删颜色同时配合符号，不能只靠颜色传达含义。
- 所有按钮、输入框和弹窗具备 hover、focus-visible、disabled、loading、empty 和 error 状态。
- 历史 Review 与模板页共享导航、排版和表面样式，业务逻辑不变。

## 前端组件与状态

- `App.vue`：主导航、Review 全局状态、导出与模板等既有编排。
- `ReviewWorkspace.vue`：diff 来源、参数、请求生命周期和选中文件状态。
- `DiffSourceSelector.vue`：三种来源及 Commit、分支选择。
- `FileExplorer.vue`：树形/平铺、展开折叠、排序、评论数和选中事件。
- `fileExplorer.js`：树构建、文件分类、比较器等纯函数。
- `FileContentModal.vue`：新旧版本切换、完整内容、复制与关闭。
- 复用 `DiffFile.vue`、`ReadonlyDiffFile.vue` 的 diff 和评论展示能力。

切换来源时使旧请求失效，避免慢响应覆盖新选择。diff 更新后按路径保留选中文件，不存在时回退到首个文件。视图和排序偏好使用 localStorage；存储不可用时保持内存状态。Commit 下拉列表现有分页不属于文件列表分页移除范围。

## 文件浏览规则

- 树形节点默认目录优先、按名称自然升序；平铺按完整路径比较。
- 测试文件识别 `*.test.*`、`*.spec.*`、`*_test.go`、`test/`、`tests/`、`__tests__/`。
- 文档识别 `docs/`、Markdown、reStructuredText、AsciiDoc 和常见文档文件。
- 排序选项为默认路径、文件类型、测试文件优先、文档文件优先，并提供反向排序。
- 分类排序后仍按路径或名称作确定性次级排序，避免不同运行顺序变化。
- 树形和平铺均取消分页，列表容器连续滚动；不引入虚拟滚动，直到有真实性能数据再评估。

## diff 数据契约

新增 `DiffTypeBranch = "branch"`。`DiffRequest` 增加可选 `Base` 字段：

- `working`：沿用 `git diff HEAD` 和未跟踪文件补充。
- `commit`：沿用 `git show <commit> --format= -p`，必须提供 `commit`。
- `branch`：必须提供 `base`，执行 `git diff <base>...HEAD`。

`DiffResponse` 增加可选对比元数据，字段使用明确 Go 结构体，不使用临时 map。分支列表接口返回当前分支和本地分支列表。无效类型、缺少参数、未知 Commit、未知分支和 Git 执行失败返回可展示错误；参数通过 exec 参数数组传递，不经过 shell。

## 完整文件数据契约

新增完整文件读取接口，请求包含 diff 来源、路径、新旧侧及对应 Commit/Base 参数，响应包含 `content`、`exists`、`isBinary`。路径和侧别由请求上下文提供，不在响应中重复返回。

版本映射：

- working：旧侧为 `HEAD:<path>`，新侧为当前工作区文件；未跟踪文件旧侧为空。
- commit：旧侧为 `<commit>^:<path>`，新侧为 `<commit>:<path>`；新增或删除时对应侧为空。
- branch：旧侧为 `<merge-base>:<path>`，新侧为 `HEAD:<path>`。

实现需处理重命名、重命名环、同路径删除+未跟踪新增和文本/二进制互转，拒绝绝对路径、`..` 路径穿越和仓库外解析结果。读取前根据相同参数重新计算 diff，并以 `git diff/diff-tree --raw -z -r -M` 的 NUL 元数据验证真实新旧路径，不能仅以路径位于仓库内或展示 patch 文本作为授权依据。merge commit 保留 Git 原生合并语义。Git 对象读取使用 `--` 或明确的 revision/path 参数边界；工作区读取使用 Lstat/OpenRoot/SameFile 防止符号链接逃逸，链接按 Git blob 文本处理。接口只读，不写工作区。

## 错误与安全

- 请求失败保留当前导航和参数，显示可重试错误，不展示伪造空 diff。
- 弹窗加载期间禁止旧内容冒充当前选择，切换新旧侧时同样处理请求竞态。
- 文件路径、Commit、分支名均按不可信输入验证；Review ID 使用受限字符白名单并兼容 `feature_x` 等安全旧自定义 ID，继续阻止 `..`、斜杠和控制字符。
- Commit 评论使用水合状态，加载完成前禁止编辑、保存和导出；保存、导出、初始化及模板请求均以 serial/revision 防止迟到响应覆盖新状态，Review 写操作前后端互斥。
- 不在日志、错误提示或导出中额外输出敏感文件内容。
- 保留现有本地 Review JSON 格式和嵌入静态资源构建方式。

## 验证设计

### 自动化

- Go：分支三点 diff、默认分支列表、非法来源/参数、完整文件新旧侧、未跟踪/新增/删除/二进制/空文件、路径穿越和 API 集成。
- Node 内置测试：树构建、目录优先、平铺路径、测试/文档分类、类型与反向排序。
- 每轮功能修改后运行相关测试；每轮评审修复后运行 lint、前端测试/build、`go test ./...` 和 Go build。

### 真实端到端

启动真实 Go 服务和 Vite 页面，准备包含目录、测试、文档、未提交修改及独立分支的临时 Git 仓库。亲自打开浏览器验证：

1. 三种 diff 来源及错误/空状态。
2. 树形展开折叠、平铺、全部排序、连续滚动和选中保持。
3. 完整文件新旧侧、复制、关闭和键盘交互。
4. Commit 行级评论、保存、导出、历史 Review 和模板回归。
5. 窄屏布局、键盘焦点及快速切换请求竞态。

每轮评审保存 JSON 与 HTML 报告；最终只记录实跑结果，环境缺失明确标为 SKIP。

## 交付边界

在 `feat/review-workspace-redesign` 持续开发，不为子任务另开分支。完成后回写系统设计和任务看板，清理临时产物，检查最终 diff 与 CI 等效检查。未经人类另行明确指示，不 commit、不 push、不创建 MR。
